# About project

Данный проект представляет собой работу для государственного экзамента по общей физики
3 курс МФТИ. В работе рассматривается численное решение временного уравнения Шрёдингера.
На основе этого решения создаются визуализации различных моделей, демонстрирующие изменение
волновой функции в пространстве и во времени и ее поведение при налиии различных потенциальных 
преград.

## Пять выбранных сцен

```bash
uv run models/run.py
# Только численный пробный запуск, без экспорта:
uv run models/run.py --probe --output video/selected/probes
# Перегенерация одной сцены:
uv run models/run.py --only QuantumTunnelling
```

Этот запуск создаёт **только пять GIF** в `video/selected`: туннелирование,
потенциальная яма, двухуровневый барьер, ступенька и два последовательных барьера.
Для последнего используется `TwoWall.json`: старый `TwoBariers.py` описывает
пакет между внешними стенками, а не прохождение двух отдельных барьеров.

| Сцена | Конечное физическое время | GIF с паузами |
|---|---:|---:|
| QuantumTunnelling | 330 | 18 с |
| BoxPit | 250 | 16 с |
| TwoLevelBoxPotential | 200 | 16 с |
| StepPotential | 240 | 18 с |
| TwoWall | 400 | 26 с |

Размер — 1280 × 720, 50 FPS; `--fps 25` уменьшает размер файла.
Пакеты и потенциалы сохраняют параметры исходных конфигов. Расчётная область
расширена с сохранением шага и положения исходной сетки, чтобы исключить
отражения от её границ. Длительность физического расчёта и воспроизведения
задаются отдельно в `models/render_scattering.py`. В начале и конце — пауза 1 с.
Основной масштаб плотности фиксирован на весь ролик и вмещает интерференционные
максимумы. В туннелировании прошедшая часть дополнительно показана с увеличением
×15 по вертикали. Сигма вычисляется из текущей плотности, включая разделение пакета.

Для двух барьеров к концу остаётся небольшая вероятность между ними: её дальнейшее
затухание не имеет строго конечного времени. Ролик показывает прохождение обоих
барьеров и несколько повторных отражений; остаток указан численно.

Экспорт требует `ffmpeg` в PATH. Кадры последовательно записываются во временный
FFV1-файл, затем кодируются в GIF с общей палитрой; RGB-кадры не копятся в памяти.
Рядом сохраняются JSON с проверкой нормы, сравнением с исходным решателем,
вероятностью у границ и длительностью декодированного GIF, а также PNG начала,
столкновения и конца. `--probe` выполняет 81 временной срез для каждой сцены.

## Отдельные исходные модели

Ниже описаны прежние индивидуальные скрипты и их параметры. Для пяти полных
сцен используйте `models/run.py`, как показано выше.

Для запуска используется `uv` (Python 3.11 или новее). Из корня проекта:

```bash
uv sync --locked
uv run models/QuantumTunnelling.py -i
```

Результат сохраняется в папке `video`, которая создаётся автоматически.
Основной формат — **GIF, 50 кадров в секунду**, размер одиночного графика —
1280 × 720 пикселя. Плотность вероятности показана бирюзовым, потенциал —
золотистым, действительная часть волновой функции — сиреневым (`-wf`).

По умолчанию используется презентационный режим: без осей и сетки,
с мягкой заливкой и свечением волны. Высота потенциала показана условно;
его реальные значения подписаны отдельно. Координата, импульс и сигма
вычисляются и отображаются по умолчанию. `-i` остаётся совместимым флагом,
а `--no-info` позволяет скрыть подписи.

Масштаб волны фиксируется по начальному состоянию. Действительная часть
волновой функции (`-wf`) также имеет постоянный коэффициент отображения.
Сравнительные сценарии содержат две широкие сцены одна над другой
(общий размер 1280 × 1440).

`--style scientific` возвращает координатные оси и отдельную правую шкалу
потенциала. Параметр `--pause 0.6` задаёт удержание начального и конечного
состояний по 0,6 секунды; `--pause 0` отключает паузы. Паузы увеличивают
длительность ролика, но не время моделирования.

```bash
# Научный режим с отдельной шкалой потенциала
uv run models/QuantumTunnelling.py --style scientific -wf

# GIF с волновой функцией и информацией о пакете
uv run models/QuantumTunnelling.py -i -wf

# Меньший FPS для более компактного GIF
uv run models/QuantumTunnelling.py --fps 25

# MP4 как опция (нужен установленный в системе ffmpeg)
uv run models/QuantumTunnelling.py --format mp4 --fps 60

# Поочерёдный запуск моделей
uv run models/run.py
```

Параметры `fps` и `total_frames_n` в существующих JSON-конфигах по-прежнему
задают исходную длительность ролика и время моделирования (один исходный
кадр соответствует единице времени). При экспорте число кадров пересчитывается
под `--fps`, а шаг эволюции уменьшается пропорционально. Поэтому дополнительные
кадры содержат промежуточные состояния волны, а скорость воспроизведения
сохраняется с точностью до округления на один кадр. Для GIF доступны 25 и 50 FPS:
они соответствуют целому числу сотых секунды, используемых форматом GIF.
MP4 дополнительно поддерживает 60 FPS. Скорость показа GIF также зависит от плеера.

Зависимости описаны в `pyproject.toml` и зафиксированы в `uv.lock`;
`requirements.txt` не используется. Расчёт и экспорт длинных GIF могут требовать
значительного времени и памяти. Оформление и экспорт вынесены в
`models/include/AnimationStyle.py`; численный метод матричной экспоненты сохранён.

# For developers

Папка `video` создаётся автоматически при экспорте.

На данный момент основная разработка ведется в папке models. Вся логика описывается в классах
в файлах ShrodingerEquation.py (класс волнового пакета и $\psi$- функции) и PotentialBarriers.py
(разные виды потенциальных барьеров).

Каждый файл модели является самодостаточным файлом, который можно исполнять.
```
uv run models/WavePackage.py
```

Кроме того, для автоматического тестирования большого количества моделей есть файл _run.py_. Этот 
файл создаёт пять выбранных сцен через `render_scattering.py`. Скрипт ждет завершение каждой 
модели, после чего сразу запускает следующую.

Результат работы сохраняется в папке _video_ в качестве файла _gif_ (или _mp4_ с `--format mp4`). Информация о времени работы
каждой модели можно посмотреть в _/models/info.log_.

### Вычисление эволюции

Разностная аппроксимация гамильтониана и формула $\psi(t+dt)=\exp(-iHdt)\psi(t)$
сохранены. Для вещественного стационарного потенциала гамильтониан симметричен
и трёхдиагонален. `scipy.linalg.eigh_tridiagonal` один раз вычисляет все его
собственные значения и векторы: $H=Q\Lambda Q^T$.

На каждом шаге код переводит текущую волну в собственный базис, умножает
коэффициенты на $\exp(-iE_kdt)$ и возвращается на пространственную сетку.
Полная матрица экспоненты не строится, собственные состояния не отбрасываются,
малые элементы оператора не обнуляются. Это сохраняет унитарность эволюции
с точностью до ошибок округления. Разложение кэшируется для неизменного
гамильтониана, а фазовые множители — для текущего `dt`.

Реализация и поясняющие комментарии находятся в `models/include/ShrodingerEquation.py`
и в копии `src/ShrodingerEquation.py`, используемой ноутбуком.
Интерфейс `PsiTimeEvolute(dt=1)` и возможность изменять `psi` сохранены.

### Структура json-конфига

Для того, чтобы не хардкодить численные параметры в коде  в папке _configs_ для  каждой модели написан json-конфиг, содержащий основные параметры модели.

```
[
    {
        "N" : 1000,
        "x_start" : -150,
        "x_end" : 210
    },

    {
        "x0" : -100,
        "sigma0" : 5.0,
        "E0" : 0.5
    },

    {
        "V_x0" : 70,
        "V0" : 0.55,
        "a" : 30
    }
]
```
Json-конфиг состоит из массива в котором находится 3 словаря. Первый словарь -- отвечает за параметры модели в целом: 
количество точек, на которые разделится пространственный интервал, начало и конец пространственного интервала. Второй словарь
содержит параметры волнового пакета: начальную координату, ширину и энергию. Последний словарь содержит параметры 
потенциального барьера: координату, высоту и ширину.

__NOTE:__ в конфигах для моделей HarmonicOscillator и RampPotential в параметрах потенциального 
барьера храняться обратные величины. Они помечены как _~k_ и _~omega_. То есть в коде нужно взять 
величины, обратные им _k = 1 / ~k_ и _omega = 1 / ~omega_.

# Тестирование на удаленном сервере

В процессе разработки предполагалось, что тестирование  будет происходить на удаленной машине. Предполагалось 
передавать и выгружать данные по ssh соединению, однако  в силу некоторых трудностей от этой идеи пришлось 
отказаться.

Формат конфига
```
host vs
   hostname <ip-address>
   user root
   IdentityFile <path-to-privet-key>
```

При использовании конфига, для ssh подключения достаточно ввести
```
ssh vs
```
